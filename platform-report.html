1. Platform Overview

The Slime Studio platform is a full-stack Next.js application handling online bookings with Stripe payments, an online shop, party enquiries, a subscription box service, and a comprehensive admin dashboard.

Tech Stack

Frontend

Next.js 13 App Router, React, Tailwind CSS

Backend

Next.js API routes (22 endpoints)

Database

Supabase (PostgreSQL) with Row Level Security

Payments

Stripe Payment Intents + Checkout Sessions, 3D Secure

Email

Resend API (transactional emails)

Hosting

Vercel (production deployments)

Fonts

Google Fonts — Poppins (300–600)

Icons

Mixed — SVG (admin sidebar), emoji (customer pages)

Page Inventory

Homepage

Hero, how-it-works, gallery preview, why-choose-us, CTA

Booking

Calendar, time slots, Stripe payment, 3DS, success page

Shop

Product catalogue, category filters, cart, Stripe checkout

Parties

Info page, tiered pricing, what's included, enquiry form

About

Image carousel, studio story, feature cards, CTAs

Gallery

Static emoji placeholder grid (no real photos)

FAQs

Static 10-question list

Contact

Info cards + enquiry form to Supabase

Subscribe

Slime subscription box, Stripe checkout, success/cancel

Admin Login

Token-based auth, session cookie

Admin Dashboard

Overview, bookings, orders, shop, enquiries, revenue, subscribers, subscriptions, opening hours, content, email logs, settings, export

API Routes

22 endpoints covering bookings, payments, shop, subscriptions, auth, emails, exports

What's Working Well

  • Triple-layered capacity checks — Client, payment intent API, and confirm-booking API all verify slot and daily capacity independently
  • 3D Secure support — Stripe Elements with automatic 3DS redirect, booking details recovered from payment intent metadata
  • Idempotency protection — Duplicate booking prevention via stripe_session_id check
  • Server-side validation — Email format, past date/time prevention, slot availability against opening hours
  • Opening hours + date overrides — Admin can override weekly schedule for specific dates
  • Sortable admin table — Click any column header to sort bookings
  • Duplicate booking detection — Same name + date + time slot flagged in admin
  • Attendance tracking — Mark bookings as attended or no-show
  • Revenue dashboard — Monthly charts, payment status breakdown, subscription revenue
  • Email logging — All sent emails logged with status for audit trail
  • Maintenance mode — Site can be put into maintenance from admin settings
  • Stripe test/live toggle — Switch between test and live mode from admin
  • Cart system — Full shopping cart with quantity management and drawer UI
  • Subscription box — Monthly slime box with Stripe checkout

2. Booking System

2.1 Suggestions

#1 SMS Booking Reminders

High

Send an automated SMS reminder 24 hours before each session. The customer's phone number is already captured during booking. This would significantly reduce no-shows and last-minute cancellations. Integration via Twilio with a scheduled cron job (e.g. Vercel Cron).

Effort: 1–2 days · Ongoing cost: ~£0.04 per SMS

#2 Customer Self-Service Rescheduling

High

Currently, customers must contact the studio to change their date or time. A secure reschedule link in the confirmation email would allow customers to move their booking to another available slot (if capacity allows) without admin involvement. No refund needed — just update the date/time.

Effort: 2–3 days

#3 "What to Expect" Information on Booking Page

Medium

The booking page doesn't currently explain what happens during a session. A short info box covering age guidance, what to wear, session duration, what's included, and parking info would set expectations and reduce pre-booking enquiries.

Effort: 2 hours · Requires: Content from client

#4 Customer Self-Service Cancellation

Medium

Allow customers to cancel their own booking via a secure link in the confirmation email, with an automatic Stripe refund. Requires a cancellation policy decision (e.g. full refund up to 48 hours before, no refund within 48 hours). Currently all cancellations are admin-handled.

Effort: 1–2 days · Requires: Cancellation policy decision

#5 Waitlist for Full Slots

Low

When a slot is full, customers see "Full" and must try another slot. A waitlist would capture their interest and automatically notify them if a spot opens up from a cancellation. This maximises capacity utilisation and captures demand data.

Effort: 2–3 days

#6 Time Ranges on Slot Selection

Low

Time slots currently show "11:00" but not the session end time. Displaying "11:00–12:00" would make it clearer that sessions are one hour and help customers plan their day.

Effort: 30 minutes

#7 Group / Family Booking Names

Low

Currently a booking has one name. For groups, it would be useful to capture the names of all attendees (especially for parties and school trips). This helps with check-in and safety registers.

Effort: 1 day

2.2 Missing Features

#8 Booking Reference in Confirmation Email

Missing

The booking confirmation email sent via Resend does not include the booking reference number. The success page shows it, but the email doesn't. Customers can't reference their booking when contacting the studio.

Effort: 1 hour

#9 Reschedule / Cancel Link in Email

Missing

The confirmation email contains no actionable links for the customer to reschedule or cancel. They must phone or email the studio. See suggestions #2 and #4 above.

Effort: Covered by #2 and #4

#10 Booking Calendar on Success Page — Add to Calendar Button

Missing

The booking success page shows the session details but doesn't offer an "Add to Calendar" button (Google Calendar / Apple Calendar / Outlook). This would help customers remember their session and reduce no-shows.

Effort: 1 hour

2.3 Bugs & Issues

#11 Revenue Page Counts All Bookings in Total

Bug

The revenue page at /dashboard/revenue shows "Total Revenue" which sums total_price for ALL bookings including unpaid, expired, and refunded. This inflates the figure. The "Paid Revenue" figure is correct, but the "Total Revenue" headline number is misleading. Should either be labelled "Gross (incl. unpaid)" or only count paid.

Effort: 30 minutes

#12 Calendar Date Construction Fragility

Bug

In /app/dashboard/bookings/page.tsx, the admin calendar constructs ISO date strings manually with string padding (e.g. `${y}-${String(m).padStart(2,'0')}-${String(d).padStart(2,'0')}`) instead of using toISOString(). This is fragile and could break across timezone edges. Should use proper date utilities.

Effort: 1 hour

#13 BookingCard Notes Still Uses Emoji

Bug

The BookingCard component in the admin bookings page still renders 📝 {b.notes} with an emoji prefix. The rest of the admin was cleaned up to use SVG icons, but this was missed.

Effort: 5 minutes

3. Online Shop

Note: The shop is currently in "coming soon" mode with a countdown timer. The product catalogue, cart, and checkout are all built and functional — just hidden behind the shopLive flag in shop_settings. The suggestions below apply to when the shop goes live.

3.1 Suggestions

#14 Product Reviews & Ratings

High

Allow customers to leave star ratings and reviews on shop products. Social proof drives conversions significantly. Reviews could be collected post-purchase via a follow-up email asking customers to rate their items.

Effort: 2–3 days

#15 Post-Purchase Review Email

High

Automatically email customers 7 days after their shop order to ask for a product review and offer a discount code for their next purchase. This builds reviews, encourages repeat purchases, and strengthens the email list.

Effort: 1–2 days

#16 Discount Codes / Promotions

Medium

The shop has no discount code system. Adding promo codes (percentage off, fixed amount, free shipping) would enable seasonal promotions, influencer collaborations, and customer retention campaigns. Stripe Coupons can handle this server-side.

Effort: 1–2 days

#17 Product Search & Sorting

Medium

The shop has category filters but no search bar or sort options (price low-high, newest, popular). As the catalogue grows, customers will need to search and sort to find products. A simple text search + sort dropdown would suffice.

Effort: 1 day

#18 Related Products / Cross-Sell

Low

Show "You might also like" suggestions on product pages and at checkout. E.g. if buying a DIY kit, suggest slime accessories. This increases average order value.

Effort: 1–2 days

#19 Product Detail Pages

Low

Currently products appear to be displayed via ProductCard components in a grid. If there are no individual product detail pages (with larger images, full description, ingredients/safety info), these should be added. Especially important for slime products which may need safety/age warnings.

Effort: 1–2 days

3.2 Missing Features

#20 Shop Order Tracking / Status Notifications

Missing

Shop orders go from "paid" to nothing. There's no order status tracking (Processing → Packed → Shipped → Delivered) and no email notifications at each stage. Customers will inevitably ask "where's my order?" The admin orders page can update payment_status but there's no fulfilment status field.

Effort: 1–2 days

#21 Shipping Cost Configuration

Missing

The ShopOrder type has shipping_cost and shipping_method fields, but there's no admin UI to configure shipping rates. Are these hardcoded? The client needs to be able to set delivery costs, free shipping thresholds, and collection vs delivery options.

Effort: 1 day

#22 Out-of-Stock Product Handling

Missing

The admin dashboard shows a low-stock alert (≤5 units), but there's no visible "Out of Stock" badge or disabled state on the customer-facing ProductCard. Products with 0 stock should either be hidden or shown as unavailable with a "Notify me" option.

Effort: 2 hours

3.3 Bugs & Issues

#23 Shop "Coming Soon" Gift Card Text Mismatch

Bug

The shop's "coming soon" page mentions "Our gift cards are available!" and shows a gift card visual, but there's no actual gift card purchase flow. This is misleading to customers. Either remove the gift card mention or implement gift card functionality (see #36).

Effort: 5 minutes to remove, 2–3 days to implement

4. Party Bookings

4.1 Suggestions

#24 Party Booking Online Payment

High

Party bookings currently use an enquiry form with no online payment. Adding Stripe checkout for party deposits (e.g. £50 non-refundable deposit) or full payment would secure bookings and reduce no-shows. The tiered pricing logic (priceForCount) already exists — it just needs payment integration.

Effort: 2–3 days

#25 Party Add-Ons (Food, Cake, Party Bags)

Medium

The party page lists what's included but there are no optional add-ons. Common party extras: party food, birthday cake, party bags, extra time, extra children. These could be selectable during the booking process with incremental pricing.

Effort: 2 days

#26 Party Calendar Availability

Medium

The party enquiry form has a date picker but doesn't check studio availability. The client has to manually check and confirm. Integrating the existing opening hours / date overrides system would show only available party dates and prevent double-booking.

Effort: 1–2 days

#27 Party Themes

Low

Offer themed party packages (e.g. "Unicorn Slime Party", "Galaxy Slime Party", "Halloween Slime Party") with themed colours, decorations, and slime types. This adds variety and premium pricing potential.

Effort: 1 day (dev) · Requires: Theme content from client

4.2 Missing Features

#28 Party Enquiry Auto-Reply Email

Missing

When a party enquiry is submitted, it's saved to the enquiries table in Supabase, but no email is sent to the customer confirming receipt. They see a "Sent!" screen but receive nothing in their inbox. An auto-reply email would reassure them and set expectations for response time.

Effort: 1 hour

#29 Admin Notification for Party Enquiries

Missing

Party enquiries are saved to the database but there's no email notification sent to the studio. The admin has to manually check the enquiries dashboard. A notification email (like the one sent for regular bookings) would ensure timely responses.

Effort: 1 hour

#30 Party Enquiry — Structured Data Fields

Missing

The party enquiry form packs all data (date, children count, phone) into a single message string. This makes it hard to filter, sort, or report on party enquiries in the admin. The enquiries table has enquiry_type, preferred_date, and phone fields that aren't being used for party submissions.

Effort: 2 hours

5. Admin Dashboard

5.1 Suggestions

#31 Revenue Analytics Dashboard

High

The dashboard shows basic revenue stats (today, week, month) and an 8-week bookings chart. A proper analytics view with revenue trends, booking conversion rates, average group size, peak hours heatmap, shop sales breakdown, and period-over-period comparisons (e.g. "up 23% vs last month") would give actionable business insights.

Effort: 2–3 days

#32 Staff Multi-User Access with Roles

Medium

Currently there appears to be a single admin login. Adding multi-user support with role-based permissions (e.g. full admin vs front-desk staff who can only view/edit bookings but not change settings or view revenue) would be important as the business grows and hires staff.

Effort: 2–3 days

#33 Automated Low-Stock Email Alerts

Medium

The dashboard shows a low-stock count but doesn't proactively notify. An email alert when a product drops below a threshold (e.g. 5 units) would help the client reorder in time before selling out.

Effort: 1 day

#34 CSV Export of Bookings/Orders

Medium

The admin has iCal export for bookings but no CSV/Excel export. A CSV export of filtered bookings and shop orders (with all fields) would be useful for accounting, import into other tools, and sharing with staff who don't have dashboard access.

Effort: 2 hours

#35 Google Calendar Two-Way Sync

Low

iCal export exists, but a direct Google Calendar integration (two-way sync) would let the client see bookings alongside other appointments. Could also block time slots when the client marks themselves unavailable in Google Calendar.

Effort: 2–3 days

5.2 Missing Features

#36 Gift Voucher System

The admin orders page can update payment_status but there's no fulfilment workflow (Processing → Packed → Shipped → Delivered). No way to track which orders need packing, which are shipped, etc. See also #20.

The admin has a "Content" page that can edit homepage, parties, and about text. But the gallery photos and FAQs are hardcoded in the page files — the client cannot update them without developer help. These should be database-driven and editable from the admin.

The admin sidebar includes a "Blocked Dates" link at /dashboard/blocked-dates, but this functionality was replaced by Date Overrides in the Opening Hours page. The blocked dates page may be redundant or broken. Should be removed from the sidebar or redirect to opening hours.

9. Security & Performance

9.1 Suggestions

#69 Rate Limiting on API Routes

Medium

API routes like /api/create-payment-intent, /api/confirm-booking, and the enquiry submission endpoints have no rate limiting. A malicious actor could spam the endpoints. Adding basic rate limiting (e.g. via Vercel's built-in limits or a simple IP-based throttle) would protect against abuse.

Effort: 1 day

#70 Image Optimisation

Medium

All images across the site use standard <img> tags with local paths (e.g. /images/slime_mixing.jpg.jpeg). Next.js <Image> component would provide automatic optimisation, lazy loading, responsive sizing, and WebP conversion — significantly improving page load times and LCP scores.

Effort: 1–2 days (site-wide migration)

#71 Admin Auth — Password Hashing Verification

Low

The admin login uses a token-based system with password_hash stored in the database. Should verify that passwords are properly hashed with bcrypt or argon2 (not plain text or weak hashing) and that the session token has a reasonable expiry.

Effort: 2 hours (audit and fix if needed)

#72 Supabase RLS Policy Audit

Low

The customer-facing pages use the anon Supabase client (supabase) which is subject to RLS. The admin and webhooks use supabaseAdmin which bypasses RLS. Should verify that RLS policies are properly configured so customers can only read public data and insert enquiries/bookings — not read other customers' bookings or modify data.

Effort: 2 hours (audit)

9.2 Bugs & Issues

#73 Client-Side Capacity Checks Use Anon Supabase

Bug

The booking page (/app/booking/page.tsx) performs client-side capacity checks using the anon supabase client, querying bookings with .eq("payment_status", "paid"). If RLS policies restrict access to the bookings table, these queries could return empty results, making the client think there's availability when there isn't. The server-side checks in the payment intent API are the real protection, but the client-side checks should work correctly too. Verify RLS allows reading aggregate booking data for availability checks.

Effort: 1 hour (verify and fix RLS if needed)

11. Technical Debt

#79 Inconsistent Icon System

Medium

The platform uses a mix of SVG icons (admin sidebar, cart, social links) and emoji icons (homepage, contact, about, parties, dashboard stat cards, booking card notes). This creates visual inconsistency and cross-platform rendering issues. A unified SVG icon system should be used everywhere.

Effort: 1 day (site-wide cleanup)

#80 Hardcoded Colours Instead of Design Tokens

Medium

Many pages use hardcoded hex colours (e.g. #ff2d78, #ffc4fb, #abf7dc, #64d8ec) instead of the Tailwind design tokens (bg-sky-blue-light, bg-bright-lavender, etc.). This makes global colour changes difficult and inconsistent. All colours should use the defined Tailwind custom colours.

Effort: 1 day (site-wide refactor)

#81 Image File Extensions

Low

Image files have double extensions (e.g. slime_mixing.jpg.jpeg, pink_slime_action.jpg.jpeg). This is unusual and could cause issues with some tools or CDN configurations. Should be renamed to standard single extensions.

Effort: 1 hour (rename + update references)

#82 No Error Boundaries

Low

No React Error Boundaries are defined. If a component throws during render, the entire page crashes with a white screen. Adding error.tsx files in the app router would provide graceful fallback UI.

Effort: 2 hours

#83 No Loading.tsx Files

Low

No Next.js loading.tsx files are defined. Adding skeleton loaders or spinners at the route level would improve perceived performance for server-rendered pages.

Effort: 1 hour
